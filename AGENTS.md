# Правила проекта ML_task_zero

Репозиторий содержит исследование и научный аудит исходного учебного проекта и отдельный небольшой проект по механике.

## Структура и границы этапов

- `01_structure.md`, `02_audit.md`, `log.md` — отчёты и журнал; `README-upstream.md` — исходный README.
- Исходные скрипты расположены в корне и остаются неизменёнными в рамках пунктов 1–2.
- `own-project/` — собственная реализация пункта 3.
- `Итоговый отчет.md` — единый краткий отчёт по всем частям задания.
- Исследование структуры и научный аудит выполнять чтением. Не исправлять upstream-код.

## Изменения собственного проекта

Реализацию можно свободно менять, если проверяемые свойства сохраняются. До принятия изменений запускать форматирование и статический анализ, регрессионные тесты, пользовательские примеры, независимые проверки размерностей/физических инвариантов/предельных случаев, а также воспроизводимые измерения времени и памяти, когда они заявлены. Новый функционал покрывать тестами. Не утверждать прохождение проверок, если они не запускались.

Изменения физических предположений объяснять и проверять отдельными предметными тестами. Для формул указывать вывод или первоисточник. В собственном проекте использовать SI: μ в м³/с², радиус в метрах, время в секундах, скорость в м/с. Исходный проект задаёт G=1 без объявленной системы единиц; не называть его значения SI.

## Воспроизводимость

Фиксировать Git commit исходников, SHA-256 кода и входных данных, конфигурацию модели/эксперимента, разбиение данных при наличии, seed и число запусков, версии Python/библиотек, платформу, команды и логи метрик. Если обучения, случайности или внешних данных нет — явно так и писать. Итоговые таблицы строить из сохранённых результатов.

Параметры, единицы, ограничения и исключённые эффекты документировать. Для этого проекта разрешены pytest, Ruff и ty; версии инструментов фиксировать lock-файлом. GitHub Actions обязан запускать тесты, форматер, линтер, ty и проверку синхронизации отчёта с CSV/метаданными. Не принимать отчёт с устаревшей таблицей. Новые внешние зависимости фиксировать и обосновывать.

Работать с `st115592/ML_task_zero` и локальной папкой, заданной автором. Не удалять исходные файлы и не изменять upstream-код в рамках пунктов 1–2. Не публиковать секреты и личные данные. Публикация в другие репозитории или действия вне текущего запроса требуют отдельного разрешения.
